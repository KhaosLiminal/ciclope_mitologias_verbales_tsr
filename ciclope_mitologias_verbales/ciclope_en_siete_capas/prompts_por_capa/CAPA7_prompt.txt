## PROHIBICIONES ABSOLUTAS

1. NO usar nombres reales de instituciones, personas, programas ni proyectos
2. NO inventar estadísticas, porcentajes, cifras de impacto
3. NO usar lenguaje de "mejores prácticas" o "lecciones aprendidas"
4. NO cerrar el caso con resolución — los casos quedan abiertos
5. NO usar emojis decorativos
6. NO mencionar "TRACE v4/v5" — solo TRCO
7. NO escribir el caso como publicidad del TSR — el caso ES el problema, no la solución
8. NO incluir más de 650 palabras (mínimo 400)
9. NO usar "se logró", "se exitosamente", "resultados satisfactorios"
10. NO inventar diálogo que suene artificial — las frases textuales deben sonar reales

## MANDATOS ESTILÍSTICOS

1. Tono: Documental, sobrio, sin heroísmo. Igual que un informe de campo
2. Tiempo verbal: Presente de indicativo para la secuencia documentada
3. Frases textuales: Entre comillas, sin atribución por nombre (solo rol: "el docente", "la estudiante", "el bibliotecario")
4. Las tensiones se DESCRIBEN, no se explican. El lector deduce
5. El caso debe funcionar aunque el lector NO haya leído el TSR — el caso se sostiene solo
6. Incluir al menos 1 momento de silencio o vacío que no se pueda llenar con palabras

## PRINCIPIO DOCUMENTAL

Cada caso es un **fragmento de realidad** operado por las condiciones que el TSR
expone. No se trata de "demostrar" el TSR sino de mostrar que el patrón ya estaba
allí, operando, antes de que nadie lo nombrara. El caso no valida la teoría;
la teoría hace legible el caso.

ESTE PRINCIPIO NO SE NEGOCIA.
